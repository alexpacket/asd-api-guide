Foundations

What ASD is, and what it is not

ASD is one of the Cisco Support APIs: a REST (Representational State Transfer) API with JSON (JavaScript Object Notation) bodies that returns software metadata for a device and then a short-lived, per-session download URL for the image. It does what a person does on the software download site (pick a release, read the checksum, accept the license, click download), but from a script, a pipeline or an image-management tool.

8operations, all under /software/v4.0
60 minlife of a metadataTransId and of a download URL
1–5image GUIDs (Globally Unique Identifiers) per download call
3,600 sdefault OAuth 2.0 access-token lifetime

Use ASD when

  • You run your own image repository or CI/CD (continuous integration and delivery) pipeline
  • You need checksums and release metadata in a CMDB (configuration management database) or compliance report
  • You build a tool for many platforms that no single controller manages

Prefer something else when

  • The devices are already managed by Catalyst Center or Intersight: let the controller fetch the image
  • You only need to know which release to run: Software Suggestion v2 answers that without a download
  • The account has no SNTC or PSS entitlement: the calls will not be authorized

Use cases

Six ways customers put ASD to work. Each card says who runs it, how often, the steps and what the customer gets at the end. Start with the first one: it is the base the others build on.

1. Keep an approved image repository current

Who: network automation or platform team · Runs: nightly or weekly

  1. Choose targets (Software Suggestion or your standards)
  2. Plan file of PIDs and targets
  3. ASD metadata and download
  4. SHA-512 check
  5. File and .sha512 into the repository

Outcome: every platform in the estate has its approved image on an internal server, already verified, before anyone opens a change. Script: asd_batch.py.

2. Build the upgrade kit for a change request

Who: change owner or NOC (network operations center) · Runs: per change

  1. /metadata/pidrelease for the affected PIDs
  2. Collect release, size, SHA-512, minimum DRAM and flash
  3. Add release-note and advisory links
  4. Attach to the ticket

Outcome: the change record carries the exact file, checksum and memory prerequisites, so reviewers approve against facts and engineers stage the same file that was approved.

3. Audit images already in the field

Who: security or compliance · Runs: monthly or after an incident

  1. Export image file names and hashes from inventory
  2. /metadata/images, five names per call
  3. Compare SHA-512, flag isDeleted
  4. For advisories, /metadata/pidimage per PID

Outcome: a report of devices running images Cisco has removed from download, any file whose hash does not match Cisco's published value and, from the per-PID call, images with a software advisory, deferral notice or PSIRT flag.

4. Stage software for an air-gapped or high-security site

Who: OT (operational technology), government or regulated sites · Runs: per release

  1. Download and verify in a connected zone
  2. Carry file and .sha512 across the gap
  3. Re-verify with sha512sum -c inside

Outcome: a documented chain of custody: the hash checked on the inside is the hash Cisco published.

5. Feed lifecycle data to other tools

Who: CMDB, NetBox or ServiceNow owners · Runs: daily

  1. Metadata per PID
  2. Store isSuggested, lifeCycle, psirtIndicator, advisories, fcsDate
  3. Join to inventory

Outcome: dashboards that show which platforms are behind the suggested release or carry a security advisory, without anyone browsing the download site.

6. Cover platforms no controller manages

Who: teams with mixed estates (firewalls, routers, optics, appliances) · Runs: as needed

Catalyst Center and Intersight fetch images for what they manage. ASD covers the rest with one workflow, so the repository and audit in use cases 1 and 3 can include every Cisco platform the contract covers.

Entitlement and onboarding

Access is gated twice: once to reach the API at all, and again on every download, against the contracts on the Cisco.com profile behind the app. Most failed ASD projects stall here, not in code.

  1. SNTC or PSS contract
  2. API Developer role (CSAM)
  3. Register app in API Console
  4. Add "Automated Software Distribution"
  5. Contracts on the Cisco.com profile
  6. Software download access (ART)
StepCustomer (SNTC)Partner (PSS)
1. EntitlementSmart Net Total Care. Complete the SNTC portal onboarding guide.Partner Support Service. The partner must hold at least one valid SNTC contract with the customer organization it acts for.
2. API roleThe company's Delegated Administrator grants the API Developer role in CSAM (Cisco Services Access Management).Request access to PSS APIs and the API Console from the PSS community page, quoting a PSS contract number. A TAC engineer grants it; allow up to 48 hours.
3. App registrationCisco API Console (apiconsole.cisco.com) > My Apps & Keys > Register a New App > OAuth 2.0 grant Client Credentials only > select the Support APIs. The Client ID and Secret do not expire but can be regenerated; treat them like a password.
4. ASD visible?ASD must appear under Select APIs on the Register a New App form before your app can be given access. If it is missing, the role or entitlement is not in place yet. The console's documentation list also has an "Automated Software Distribution Preview-V3" entry (released 21 Nov 2024, no documentation) with a Request Access button; ask swc-it-support@cisco.com which entry applies to you before requesting.
5. Download entitlementEach registration carries the identity and permissions of the API user who created it. Images that need a contract return metadata but no URL until the contract is on that user's Cisco.com profile (Profile Manager).
6. Software download accessContract-registered software can return IAC_ERROR until the user is granted Software Download Access through Cisco's ART access-request site (edsart.cloudapps.cisco.com): Cisco Service > Connected Experience (CX) > Delivery & Tools Support > Software Download and Special File Publishing Access.

Use a dedicated Cisco.com identity for automation. Downloads are authorized against the profile behind the app, so a personal login means the pipeline breaks when that person leaves or their contract associations change.

Authentication

One OAuth 2.0 client-credentials request returns a Bearer token that every Support API accepts. The token lasts 3,600 seconds by default; cache it and renew a few minutes early rather than per call.

Shell · get an access token
curl -s -X POST https://id.cisco.com/oauth2/default/v1/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "grant_type=client_credentials" \
  --data-urlencode "client_id=$CISCO_CLIENT_ID" \
  --data-urlencode "client_secret=$CISCO_CLIENT_SECRET"

# 200 OK
# {"access_token": "Er2cdpFDGNsQ...", "token_type": "Bearer", "expires_in": 3599}

Workflow

Deploy it in five steps

For a customer standing up ASD automation for the first time. Steps 1 and 2 are paperwork and can take a few days; steps 3 to 5 take an afternoon.

Step 1 · Confirm access

Check the customer has SNTC (or works through a PSS partner) and that the automation's Cisco.com identity has the API Developer role and the right contracts on its profile. See Entitlement and onboarding.

Done when: "Automated Software Distribution" is selectable on the API Console's Register a New App form.

Step 2 · Register the app

API Console > My Apps & Keys > Register a New App. Application type Service, grant type Client Credentials, APIs: Automated Software Distribution and Software Suggestion API V2.

Done when: you have a Client ID and Client Secret.

Step 3 · Store the secret and test one PID

Put the ID and secret in the customer's secrets store (vault, CI variables), never in code. Run the Python client against one PID the customer owns.

Shell · first test
pip install requests
export CISCO_CLIENT_ID=…  CISCO_CLIENT_SECRET=…
python asd_client.py C9300-48P 17.9.4

Done when: the image downloads and prints "SHA-512 verified". If it prints exception codes instead, look them up in Errors and exceptions.

Step 4 · Write the plan file and run the batch

One row per platform: the PID, the release it runs today, and the target. The batch script downloads each approved image once, verifies it, writes a .sha512 file beside it, and prints a JSON report. It exits non-zero if anything was blocked or failed, so a scheduler can alert.

CSV · plan.csv
pid,current_release,target
C9300-48P,17.9.4,latest
C9500-48Y4C,17.9.4,17.12.6
ISR4451-X/K9,17.6.5,above
Python 3 · asd_batch.py (same folder as asd_client.py)
# asd_batch.py: nightly refresh of an image repository from a plan file
# plan.csv columns: pid,current_release,target   (target = latest | above | a release such as 17.12.6)
import csv, json, os, sys, time
from asd_client import ASDClient

REPO = os.environ.get("ASD_REPO", "./images")
os.makedirs(REPO, exist_ok=True)
c = ASDClient(os.environ["CISCO_CLIENT_ID"], os.environ["CISCO_CLIENT_SECRET"])
report = []

for row in csv.DictReader(open(sys.argv[1])):
    pid, cur, tgt = row["pid"], row["current_release"], row.get("target") or "latest"
    try:
        meta = c.metadata_by_release(pid, cur, tgt)
        rows = list(c.images(meta))
        ok = [r for r in rows if not r["exceptions"]]
        if not ok:   # metadata came back, but every image is gated
            report.append({"pid": pid, "status": "blocked",
                           "codes": sorted({e for r in rows for e in r["exceptions"]})})
            continue
        pick = ok[0]
        dest = os.path.join(REPO, pick["name"])
        if os.path.exists(dest):
            report.append({"pid": pid, "status": "already in repo", "image": pick["name"]}); continue
        d = c.download_urls(pid, pick["mdfId"], [pick["guid"]], meta["metadataTransId"])
        item = d["downloads"][0]
        if item.get("exception"):
            report.append({"pid": pid, "status": "blocked",
                           "codes": [e.get("code") for e in item["exception"]]}); continue
        sha = c.fetch(item, dest + ".part")
        if pick["sha512"] and sha.lower() != pick["sha512"].lower():
            os.remove(dest + ".part")
            report.append({"pid": pid, "status": "checksum mismatch", "image": pick["name"]}); continue
        os.rename(dest + ".part", dest)
        with open(dest + ".sha512", "w") as f:
            f.write(f'{pick["sha512"]}  {pick["name"]}\n')
        report.append({"pid": pid, "status": "downloaded", "image": pick["name"], "release": pick["release"]})
    except Exception as e:      # one bad PID must not stop the run
        report.append({"pid": pid, "status": "error", "detail": str(e)[:200]})
    time.sleep(2)               # stay well under the per-second limit

print(json.dumps(report, indent=2))
sys.exit(1 if any(r["status"] in ("blocked", "error", "checksum mismatch") for r in report) else 0)

Tested against the same local mock as the client: download, verification, and skip-if-present on a second run.

Step 5 · Schedule it and watch the report

Run nightly from cron or the CI system, keep the JSON report, and alert on blocked, error or checksum mismatch. Blocked usually means a contract, EULA or K9 action for a person, not a code fix.

Shell · crontab entry (02:15 daily)
15 2 * * * cd /opt/asd && ASD_REPO=/srv/images python3 asd_batch.py plan.csv > report-$(date +\%F).json 2>&1 || /opt/asd/alert.sh

Done when: a night's run leaves new images and a clean report, and a forced failure (a bad PID) raises an alert.

Find images: the three metadata calls Read only

All three return the image names, sizes and checksums. The first two also return the metadataTransId and mdfId (Cisco's product catalog ID, from the Metadata Framework) that the download call needs. Pick the call by what you already know.

Always inspect exception[ ]

A metadata call can return HTTP 200 with an exception code on an image, such as IMG_CONTRACT_REQD or IMG_K9. The metadata is real, but no download URL will follow until the cause is fixed.

Signals worth storing

isSuggested, lifeCycle, psirtIndicator (Product Security Incident Response Team advisory attached), softwareAdvisory, deferralNotice, isDeleted, additionalEntitlement.

PID format

One PID per call. Cisco's example shows a full UDI-style value (ACS-1800-RM-19=VID:V01); a base PID such as C9300-48P is the usual input. If you get NO_DATA_FOUND_FOR_PID, check the PID and try the base PID without suffixes.

Workflow

EULA and K9 gates

Some images need a signed EULA, and strong-encryption images need the K9 export form. You read the current text with a GET and record acceptance with a POST. The gates show up as exception codes (EULA_FORM_AR, K9_FORM_AR, K9_EULA_FORM_AR, K9_IMG_DWLD) or as eulaContent and k9Content in the download response.

OperationPurposeBody
GET /compliance/eulaCurrent EULA text, accept and decline values, webForm link, subAppVersionNone
POST /compliance/eulaRecord acceptance or declinestatus (Accepted | Declined), fileNames, declineComments if declined
GET /compliance/k9K9 form fields and values, user details, webForm linkNone
POST /compliance/k9Record the K9 answersstatus, busFunction (COMM_OR_CIVIL), confirm (CONFIRM_CHECKED), govMilCountries, fileNames (one), declineComments if declined

These are legal attestations, not plumbing. A POST to /compliance/k9 certifies export-control answers for the organization, on behalf of the Cisco.com identity behind the app. Have the person entitled to make that statement accept it once, interactively (the webForm links to software.cisco.com/download/k9 and /eula), and do not hard-code acceptance into an unattended pipeline. A rejected K9 (K9_REJECTED) is reviewed by Cisco; the documented retry window is about four hours.

Python client

A complete client: token caching with early renewal, the three metadata shapes flattened into rows, exception-aware selection, both download modes, streamed SHA-512 verification, and backoff on the 403 rate-limit responses ASD uses instead of 429. It was run end to end against a local mock of the documented request and response shapes (token, metadata, a K9-blocked image skipped, download URL, 302 redirect, checksum). It has not been run against Cisco's production API.

Python 3 · asd_client.py (needs requests)
# asd_client.py: Cisco Automated Software Distribution (ASD) API v4.0 client
# token cache, metadata lookup, EULA/K9 check, download URL, streamed download, SHA-512 check
import hashlib, os, sys, time, requests

TOKEN_URL = "https://id.cisco.com/oauth2/default/v1/token"
ASD = os.environ.get("ASD_BASE", "https://apix.cisco.com/software/v4.0")

class ASDClient:
    def __init__(self, client_id, client_secret, token_url=TOKEN_URL, base=ASD):
        self.cid, self.sec, self.token_url, self.base = client_id, client_secret, token_url, base
        self.s = requests.Session(); self.tok = None; self.exp = 0

    def token(self):
        if time.time() < self.exp:
            return self.tok
        r = self.s.post(self.token_url, data={"grant_type": "client_credentials",
                        "client_id": self.cid, "client_secret": self.sec}, timeout=30)
        r.raise_for_status(); j = r.json()
        self.tok = j["access_token"]
        self.exp = time.time() + int(j.get("expires_in", 3600)) - 300   # renew 5 min early
        return self.tok

    def post(self, path, body):
        for attempt in range(4):
            r = self.s.post(self.base + path, json=body, timeout=60,
                            headers={"Authorization": f"Bearer {self.token()}"})
            # The ASD error table reports rate and quota limits as 403, not 429
            if r.status_code in (403, 429, 502, 503, 504) and attempt < 3:
                if r.status_code == 403 and "Rate" not in r.text and "Over" not in r.text:
                    break                                  # a real permission error: stop
                time.sleep(2 ** attempt * 5); continue
            break
        if r.status_code >= 400:
            raise RuntimeError(f"{path} -> HTTP {r.status_code}: {r.text[:300]}")
        return r.json()

    @staticmethod
    def images(meta):
        """Flatten metadata -> products -> softwareTypes -> operatingSystems -> releases -> images."""
        for m in meta.get("metadata", []):
            for p in m.get("products", []):
                for st in p.get("softwareTypes", []):
                    for os_ in st.get("operatingSystems", []):
                        for rel in os_.get("releases", []):
                            for img in rel.get("images", []):
                                yield {"pid": m.get("pid"), "mdfId": p.get("mdfId"),
                                       "release": rel.get("version") or rel.get("releaseVersion"),
                                       "suggested": rel.get("isSuggested"),
                                       "name": img.get("name") or img.get("imageName"),
                                       "guid": img.get("imageGuid"),
                                       "size": img.get("size") or img.get("imageSize"),
                                       "sha512": img.get("sha512"), "md5": img.get("md5"),
                                       "exceptions": [e.get("code") for e in img.get("exception", [])]}

    def metadata_by_release(self, pid, current, output="latest", page=1):
        # Field casing follows Cisco's sample request; the parameter table spells some differently
        return self.post("/metadata/pidrelease", {"pid": pid, "currentReleaseVersion": current,
                         "outputReleaseVersion": output, "pageIndex": str(page), "perPage": "25"})

    def metadata_by_image(self, pid, image_names):
        return self.post("/metadata/pidimage", {"pid": pid, "imageNames": image_names[:5],
                         "pageIndex": "1", "perPage": "25"})

    def accept(self, kind, file_name):
        # kind is "eula" or "k9"; only call after reviewing the agreement with the right owner
        body = {"status": "Accepted", "fileNames": file_name}
        if kind == "k9":
            body.update({"busFunction": "COMM_OR_CIVIL", "confirm": "CONFIRM_CHECKED"})
        return self.post(f"/compliance/{kind}", body)

    def download_urls(self, pid, mdf_id, guids, trans_id):
        return self.post("/download/pidimage", {"pid": pid, "mdfId": str(mdf_id),
                         "imageGuids": guids[:5], "metadataTransId": trans_id})

    def fetch(self, item, dest):
        """Stream one entry of downloads[] to disk; returns the SHA-512 of the bytes written."""
        h = hashlib.sha512()
        if item.get("token"):    # image is in Cisco's cloud store: form-encoded POST, follow 302s
            r = self.s.post(item["url"], data={"X-Authentication-Control": item["token"]},
                            stream=True, allow_redirects=True, timeout=600)
        else:                    # default download URL: append the API access token
            r = self.s.get(item["url"] + "&access_token=" + self.token(),
                           stream=True, allow_redirects=True, timeout=600)
        r.raise_for_status()
        with open(dest, "wb") as f:
            for chunk in r.iter_content(1 << 20):
                f.write(chunk); h.update(chunk)
        return h.hexdigest()

if __name__ == "__main__":
    pid, current = sys.argv[1], sys.argv[2]
    c = ASDClient(os.environ["CISCO_CLIENT_ID"], os.environ["CISCO_CLIENT_SECRET"])
    meta = c.metadata_by_release(pid, current, "latest")
    trans = meta["metadataTransId"]                       # valid for 60 minutes
    imgs = list(c.images(meta))
    for i in imgs:
        print(f'{i["release"]:<14} {i["name"]:<48} {i["size"]:>12}  {",".join(i["exceptions"]) or "ok"}')
    ok = [i for i in imgs if not i["exceptions"]]
    if not ok:
        sys.exit("No downloadable image: resolve the exception codes above first")
    pick = ok[0]
    d = c.download_urls(pid, pick["mdfId"], [pick["guid"]], trans)
    item = d["downloads"][0]
    if item.get("exception"):
        sys.exit(f'Download blocked: {[e.get("code") for e in item["exception"]]}')
    got = c.fetch(item, item["imageName"])
    if pick["sha512"] and got.lower() != pick["sha512"].lower():
        os.remove(item["imageName"]); sys.exit("SHA-512 mismatch: file deleted")
    print(f'{item["imageName"]} downloaded and SHA-512 verified')

Software Suggestion v2: which release?

ASD says what exists and lets you download it. Software Suggestion says what Cisco recommends, based on stability, longevity, adoption rate and other factors. Use it first to choose the target, then hand the release to ASD. All operations are GET on https://apix.cisco.com/software/suggestion/v2/suggestions/…, with the same Bearer token, once the app has access to "Software Suggestion API V2".

PathReturns
/software/productIds/{productIds}Suggested releases and their images for a list of PIDs
/releases/productIds/{productIds}Suggested releases without images
/compatible/productId/{basePID}Compatible and suggested releases for one PID, filterable by currentImage, currentRelease, supportedFeatures
/software/mdfIds/{mdfIds}, /releases/mdfIds/{mdfIds}, /compatible/mdfId/{mdfId}The same three views keyed by MDF ID

  "https://apix.cisco.com/software/suggestion/v2/suggestions/releases/productIds/C9300-48P,C9500-48Y4C?pageIndex=1"

Community threads report empty or wrong suggestions for some PIDs (retired platforms, some Nexus and Catalyst 9500 PIDs, and a 5508 wireless controller case). Treat a suggestion as input to a decision, and cross-check it against release notes and field notices before it drives an automated upgrade.

Product Information: getting the MDF ID

The download call needs the mdfId. The metadata calls already return it, so you rarely need this, but the Product Information API maps PIDs to MDF IDs directly, which helps when you key a repository by MDF ID or call Software Suggestion by MDF ID.

Shell · PID to MDF ID (up to 5 PIDs)
curl -s -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://apix.cisco.com/product/v1/information/product_ids_mdf/ASA5505-50-BUN-K9?page_index=1"
# product_list[0].product_name_mdf   -> MDF ID of the product
# product_list[0].product_series_mdf -> MDF ID of the series

Note the snake_case here (page_index, product_list) against camelCase in ASD and Software Suggestion: each Support API has its own naming.

Guidance checklist

  1. Confirm entitlement first: SNTC or PSS, API Developer role, ASD visible in the API Console, contracts on the profile, ART software download access.
  2. Use a dedicated automation identity, not a person's Cisco.com login.
  3. Cache the token and renew it about five minutes before expires_in.
  4. Pick the target with Software Suggestion, download with ASD.
  5. Check exception[] on every 200. No URL follows until it is empty.
  6. Finish the download inside 60 minutes of the metadata call; on MTRANSID_EXPIRED start again from metadata.
  7. Never automate K9 or EULA acceptance silently. Have the accountable person accept once.
  8. Verify SHA-512 before an image enters the repository; delete on mismatch.
  9. Keep TLS (Transport Layer Security) verification on and keep tokens out of logs and URLs you store.
  10. Treat 403 as possibly a rate limit: read the message, back off, retry a few times.
  11. Prefer the controller when Catalyst Center or Intersight already manages the devices.
  12. Validate field names against the Swagger YAML for your account before production.
